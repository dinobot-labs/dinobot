# 전달 전 검증

게시든 전달이든 아래 검증이 모두 끝난 뒤에만 한다. 기본은 로컬 산출물 완성까지이고, 공개 게시는 사용자가 요청했을 때만 한다. 검증 결과는 있는 그대로 보고하고, 실패는 숨기지 않는다.

## 1. 사실 대조

- 글의 모든 수치를 원천 데이터(코드, 리포트, JSON)와 하나씩 대조한다. 스크립트로 존재 확인(`grep -c`)과 값 일치를 둘 다 한다.
- 수치가 여러 버전/시점 것이 섞여 있으면 출처를 각주로 구분한다. 같은 입력에 대한 비교인지, 시점이 다른 변천 기록인지 문장으로 명시한다.
- 확장 해석(성능 개선 등)은 수치가 실제로 뒷받침하는지 확인한다. 정책 변경 효과와 성능 개선을 섞어 쓰지 않는다.

## 2. 민감정보 스캔

전달(또는 게시) 직전 grep. 적중이 있으면 삭제하거나 일반화한다.

```
grep -rnoE "실명|대화ID후보|[0-9]{4,5}번대세션|/home/[a-z]+|C:\\\\|토큰패턴" --include="*.html" .
```

- 대화 ID·세션 UUID 같은 숫자 식별자 후보는 원천 목록과 대조해 실제 ID인지 확인한다. CSS 색 코드(`#1f5fbf`) 같은 오탐은 걸러낸다.
- 로컬 경로(`C:\Users\<이름>\`, `/home/<이름>/`), 계정명, 이메일, 토큰·API 키 패턴은 0건이어야 한다.
- 예시 속 사례는 "어떤 대화에서" 식으로 일반화한다.

## 3. HTML 구조

- 태그 균형 검사(파서 또는 스택 검사)에서 오류 0. void 요소와 self-closing(svg path 등) 예외 처리 주의.
- `id` 중복 0, `href="#..."` 앵커가 모두 실제 id를 가리킴 0.
- 외부 리소스(src/href의 http)는 의도한 링크만. 폰트·스크립트 CDN은 없어야 한다.

## 4. 렌더 실측

- 데스크톱 1280px 스크린샷: `msedge --headless=new --window-size=1280,높이 --screenshot=...` (긴 글은 섹션 경계로 나눠 캡처)
- 모바일 375px: **headless 창 폭을 375로 줘도 실제 뷰포트가 375가 되지 않는다.** 375px iframe 래퍼 페이지를 만들어 그 안에서 렌더하고 600px 창으로 캡처해 실측한다.
- 다크 모드: `--force-dark-mode --blink-settings=preferredColorScheme=0` 으로 강제한 스크린샷에서 가로 넘침·가독성 확인.
- 사용자가 요청해 게시한 경우에는 라이브 URL로 curl 200 확인 + 스크린샷 1장.

## 5. 문체 최종 점검

- [ ] 존댓말 기본 + 구어체 혼용이 자연스러운가 (논문체 잔재 `~된다`/`~하였다` 남용 없음)
- [ ] 각주 번호 본문↔하단 일치
- [ ] 영어 용어 괄호 병기 첫 등장 처리
- [ ] 마무리 인사와 다음 편 예고
