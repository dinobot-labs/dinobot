# 0106. Cloudflare 최초 설치와 불변 버전별 자동 업데이트

## 결정

CLI/TUI 최초 설치는 Cloudflare의 `install.sh`·`install.ps1`을 사용한다. 스크립트는 Bun 존재 여부를 확인하고 독립 설치 관리자를 실행한다. Bun 자동 설치, sudo, 전역 패키지 덮어쓰기, 실행 중 데몬 재시작은 하지 않는다. Desktop 배포는 변경하지 않는다.

## 이유

기존 전역 설치 경로를 덮어쓰면 이미 실행 중인 프로세스의 나중 import·네이티브 모듈 로드가 다른 버전 파일을 읽을 수 있다. 단순히 재시작만 생략하는 방식으로는 작업 보존을 보장할 수 없다.

## 상태 전이와 불변식

`기존 활성 버전 → 새 아카이브 검증 → 격리 설치 → 설치 결과 검증 → 불변 버전 디렉터리 공개 → 활성 포인터 변경`

- 아카이브는 기존 Cloudflare 릴리스 메타데이터와 SHA-512 검증을 재사용한다.
- 의존성 설치는 OS 임시 디렉터리의 독립 프로젝트에서 수행한다. 작업 폴더·사용자의 전역 manifest는 변경하지 않는다.
- 새 버전 설치 실패·체크섬 불일치·오프라인·동시 실행 충돌은 기존 활성 설치를 바꾸지 않는다.
- 버전 비교는 숫자 정밀도를 잃지 않는 안정 버전 비교를 사용한다. 다운그레이드는 거부한다.
- 공개한 버전 디렉터리는 덮어쓰거나 자동 삭제하지 않는다. 실행 중 코드의 지연 로드 경로를 보존한다.
- 전환 가능한 자원은 다음 실행이 읽는 활성 포인터뿐이다. 실행 중 데몬·작업 큐·하위 에이전트에는 종료·재시작 요청을 보내지 않는다.

## 적용 시점

관리형 launcher를 실행할 때 새 릴리스를 확인하고 다운로드·설치한다. 새 CLI/TUI 프로세스는 선택된 버전으로 실행한다. 이미 실행 중인 데몬은 기존 버전으로 계속 동작하며, 데몬이 자연스럽게 종료된 뒤 새 launcher로 다음 기동할 때 새 버전을 사용한다. **TUI만 닫는 것은 데몬 종료가 아니다.**

안전한 유휴 상태는 검사 직후 다시 바뀔 수 있다. 이번 설계는 busy·queued·subagent 상태를 보고 강제 전환하는 대신, 모든 상태에서 실행 중 프로세스를 유지한다. 무중단 live hot-swap이나 상시 백그라운드 업데이트 타이머를 제공한다는 의미는 아니다. 장시간 켜 둔 프로세스는 다음 launcher 실행까지 업데이트를 확인하지 않는다.

## 경계

기존 전역 설치와 소스 checkout은 자동으로 이동시키지 않는다. 새 설치가 안내하는 launcher 경로를 사용해야 관리형 업데이트가 적용된다. 이전 전역 명령이 PATH에서 우선하면 그 명령에는 이 정책이 적용되지 않는다. 기존 서비스 관리자가 옛 버전 절대 경로를 고정한 경우에도 별도 설정 변경 없이 새 버전으로 바뀌지 않는다.

공개 다운로드 신뢰 기준은 HTTPS Cloudflare origin과 해당 origin이 제공하는 SHA-512이다. 체크섬은 전송 무결성을 확인하며 별도 서명이나 origin 자체의 침해 방어를 뜻하지 않는다. 외부 의존성은 Bun이 해당 레지스트리에서 설치한다.
